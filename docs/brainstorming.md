# 项目未来发展方向 · 头脑风暴

> 基于 2026-06-14 项目现状分析
> 核心约束：海事电气与自动化仿真教学系统，面向轮机工程专业

---

## 1. 仿真引擎重构（高优先级）

### 1.1 Konva 公共库
- **现状**：21 个仿真页面各内联 300KB+ Konva v10.3.0，总计约 10MB 冗余
- **方案**：提取为 `assets/konva.min.js`，页面改为 `<script>` 引用，节省 ~7MB
- **收益**：首次加载慢页面从 575KB → 150KB，浏览器缓存全局生效

### 1.2 共享仿真框架
- **现状**：每个页面有大量重复代码（电路求解器、工作流引擎、测验系统）
- **方案**：提取以下公共模块：
  - `sim-core.js` — 电路/流体网络求解器（节点电压法、稀疏矩阵）
  - `sim-workflow.js` — 工作流引擎（自动演示/单步/评估模式）
  - `sim-quiz.js` — 测验系统（单选/多选/自动评判）
  - `sim-ui.js` — 端口连线、右键菜单、配置面板
- **收益**：新仿真页面编写成本降低 70%，一致性提升

### 1.3 设备组件库
- **现状**：设备在每页用 Konva 基元手绘（阀门、传感器、仪表盘等）
- **方案**：抽取为可复用 Konva 组件，参数化配置（量程/颜色/刻度）
- **收益**：视觉统一，避免每页重新实现

## 3. 教学功能升级

### 3.1 学生进度追踪
- **后端**：新增 `progress` 表，记录每个学生每页的完成状态
- **前端**：首页显示练习进度（已完成/总项目）
- **API**：`/api/progress/save` → `/api/progress/list`
- **复杂度**：低 — D1 已有用户系统，仅需新表 + 2 个 handler

### 3.2 自动评分系统
- **现状**：测验仅在前端评判，不保存结果
- **方案**：提交分数到后端，教师后台可查看统计
- **数据**：`scores` 表（user_id, page_id, score, max_score, timestamp）

### 3.3 理论 + 实操结合
- 为每个仿真页面添加理论知识点侧边栏
- 可折叠的 PDF/文档嵌入
- 操作步骤与知识点关联

### 3.4 操作记录回放
- 记录用户在仿真中的操作序列（拖动滑块、点击按钮 + 时间戳）
- 教师可回放学生操作，分析问题
- **技术**：IndexedDB 本地记录，可选上传

## 4. 支付与商业化

### 4.1 自动支付通道完善
- **现状**：微信/支付宝 API 调用已实现（`handlePayCreate`、`callWechatPay`、`callAlipay`），但实际流程是"用户扫个人码 → 管理员手动审核"
- **方案**：配置微信商户号和支付宝 AppID，开启自动异步回调处理（`handlePayNotifyWechat`、`handlePayNotifyAlipay` 已就绪但缺密钥）
- **优先级**：低（现有手动流程已跑通，除非需要减少人工）

### 4.2 订阅制 / 按模块付费
- 当前：¥9.9 永久解锁全部
- 可选方案：月度订阅 ¥3.9 / 按模块 ¥2.9 / 学校批量 ¥199/年
- **后端**：`orders` 表增加 `expires_at` 字段，`getAccessLevel()` 检查过期时间

### 4.3 学校/机构批量授权
- 管理员后台生成批量兑换码
- 一人一码绑定，无支付流程
- **表结构**：`vouchers`（code, batch, used_by, expires_at）

## 6. 工程化

### 6.1 构建流程
- **现状**：零构建，直接浏览器打开 HTML
- **方案**：引入 Vite 或 esbuild 做以下事：
  - 自动内联 Konva（生产）或外部引用（开发）
  - HTML 压缩
  - 公共 JS 模块打包
- **收益**：减小体积、支持开发热重载

### 6.2 类型系统
- **现状**：所有 JS 无类型
- **方案**：从 `auth.js` + `workers/src/index.js` 开始加 JSDoc 类型注解
- **收益**：VS Code 智能提示、减少运行时错误

### 6.3 测试
- **现状**：零测试
- **方案**：
  - Worker 端：vitest + miniflare（已有 `vitest.config.ts` 在模板中）
  - 前端：Playwright 做仿真页面交互测试
- **优先级**：低（项目无交付质量门禁）

### 6.4 监控与日志
- Worker 已弃用 `handleErrors` 函数，日志只 `console.log`
- 接入 Sentry 或 Workers Observability
- 关键指标：注册/登录成功率、支付转化率、页面加载性能

## 7. 用户体验

### 7.1 PWA 离线支持
- Service Worker 缓存所有 HTML 和 Konva 库
- 仿真页面可离线使用（适合船上无网络环境）
- Manifest 添加到主屏幕

### 7.2 移动端适配
- 仿真页面在手机上操作困难（Konva 拖拽需要更粗的 hit 区域）
- 增加手势支持（双指缩放、单指平移）
- 响应式布局：操作面板移到画布下方

### 7.3 暗色/亮色主题
- 当前统一暗色风格
- 提供主题切换，保存到 localStorage

### 7.4 加载体验
- 300-575KB 的页面加载时显示骨架屏或进度条
- 关键 CSS 内联，非关键 CSS 异步加载

## 8. 技术实验方向

### 8.1 WebAssembly 仿真核心
- 电路求解器等计算密集部分迁移到 WASM
- 用 Rust/C 实现，通过 wasm-pack 构建
- **收益**：复杂电路（50+ 节点）求解速度提升 5-10 倍

### 8.2 3D 可视化
- 用 Three.js 替换部分 Konva 2D 场景（机舱布局、管道系统）
- 适合需要空间感的仿真（如冷却水系统管路）

### 8.3 协作模式
- WebRTC / WebSocket 实现教师-学生远程协作
- 教师端看到学生操作实时画面
- 教师可远程标注/指导
